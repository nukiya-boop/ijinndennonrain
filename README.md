# レキシバトル オンライン(非公式ファン制作)

ダイソーの100円TCG「イジンデン」のルールを元にした、ブラウザで遊べる対戦アプリです。
Node.js + Socket.io によるリアルタイム対人対戦と、ヒューリスティックなCPU対戦に対応しています。
一切ビルド不要のバニラJSフロントエンドで構成しています。

**本アプリはダイソー/株式会社大創産業/有限会社ワンドローとは一切関係のない、非公式のファン制作物です。**
公式サイト(one-draw.jp)で公開されているルールカード・ルール補足・カードリスト(第1弾〜第6弾)を
参考にしていますが、カードイラストや商品名の商標的使用は含んでいません。

ロビー・対戦結果画面のキャラクターイラストのみ、大創出版が「告知用の印刷物・ウェブ・動画・
イベント等での使用に限り自由に使ってよい」と公開している公認素材
([イジンデン 公認素材について](https://www.daiso-syuppan.com/public/_koninsozai_ijin/))を
使用しています。Illustration / 水鳥あひる（アノアデザイン）

## 遊び方

```
npm install
npm start
```

個人利用向けにPINコードでのアクセス制限をかけたい場合は、`.env.example`を`.env`という
ファイル名でコピーし、中の`#APP_PIN=1234`の行の`#`を外して好きな数字に書き換えてください
(`.env`は`npm start`時に自動で読み込まれます)。設定した場合、初回アクセス時にPIN入力画面が
表示され、正しいPINを入力するとブラウザにセッションCookieが保存されます。`.env`を作らない/
`APP_PIN`をコメントアウトしたままにすれば、従来通りPIN入力なしでそのまま使用できます。
(`.env`ファイルはGit管理対象外なので、他の人とリポジトリを共有してもPINが漏れることはありません。)

### スマホ・他の端末からアクセスしたい場合(同じWi-Fi内)

パソコンで`npm start`したまま、スマホ側で`http://localhost:3000`を開いても繋がりません
(スマホから見た「localhost」はスマホ自身を指すため)。パソコンの画面で確認できる
LAN内IPアドレス(例: `192.168.1.5`など。Windowsなら`ipconfig`、Macなら`ifconfig`や
「システム設定→Wi-Fi→詳細」で確認できます)を使い、スマホのブラウザで
`http://(パソコンのIPアドレス):3000` を開いてください。パソコンとスマホが同じWi-Fi
ネットワークに接続されている必要があります。

### インターネット越しに公開したい場合(Vercelでは動作しません)

このアプリはNode.js + Socket.ioによる**常時起動のサーバープロセス**として作られており、
対戦部屋の状態もサーバーのメモリ上に保持しています。**Vercelのようなサーバーレス環境は
このアーキテクチャに対応していません**(サーバーレス関数は呼び出しごとに独立していて
状態を保持できず、Socket.ioが必要とする常時接続のWebSocketも維持できないため)。
Vercelにデプロイした場合、名前入力画面までは静的ファイルとして表示されますが、
「デッキ編集」「CPU対戦」などSocket.io接続が必要な操作はすべて失敗します。

常時起動のNode.jsサーバーに対応したホスティングサービス(例:
[Render](https://render.com/)の無料プラン、Railway、Fly.ioなど)へのデプロイをおすすめします。
Renderの場合、GitHubリポジトリと連携すればビルド・起動コマンドを自動検出しますが、
リポジトリに含まれる`render.yaml`を使ってBlueprintデプロイすることもできます
(Environmentタブで`APP_PIN`を設定すれば、そのままPIN認証も有効化できます)。

`http://localhost:3000` を開き、名前を入力します。「デッキ編集」で自分だけのデッキ(40枚以上、
同名カード4枚まで)を組んでおくと、それが対戦で使用されます。デッキを組んでいない場合は、
上の色から選ぶ簡易デッキ(自動生成)が使われます。

- **CPUと対戦する**: すぐにCPU(簡易AI)との1対1対戦が始まります。CPUは天草絵巻サイト
  (ijinden-amakusaemaki)で紹介されている第3弾〜第6弾の環境デッキ29種の中からランダムに
  1つを使用します。
- **対戦部屋を作る**: 発行された5文字の部屋コードを、もう一方のブラウザタブ/端末で
  「部屋に参加する」に入力すると人対人の対戦が始まります。

## 実装しているルール

- デッキ40枚、同名カード最大4枚まで(弾をまたいだ再録・別バージョンも名前単位で合算)
- 準備: 手札6枚 + ガーディアン4枚(裏向き、対戦相手だけでなく本人も中身を見られない)
- ターン: スタート→ドロー→メイン→エンドの4フェイズ
- マリョク配置権/イジン召喚権(1/ターン、ハイケイ・マホウ等での増加に対応)
- 魔力ゾーンのレベル条件・色条件(裏向きのカードはレベル1・無色として計算)、マホウの魔力コスト
- バトル: 複数ブロッカー対応、ダブル/トリプル/クアドラプルプレッシャー、ウォッチャー、即応、
  ドレイン(バトル解決で破壊した相手のカードの遺業能力を発動させない。条件付きで得るカードにも対応)
- ガーディアンのブロック判定(アタッカーのパワーが0以下の時のみガーディアンが生還)
- 勝利条件: アタックが1体でも防がれなければ即勝利/自分のターンをデッキ0枚で終えたら敗北(2025年エラッタ準拠)
- パワー0以下のイジンはアタッカー宣言不可(エラッタ準拠)
- 遺業能力のうち「Nドローする」「復元」「魔力化」「これを手札に戻す」「山札の上か下に戻す」
  「木霊(より低レベルのイジンを手札・墓地から無償で戦場に置く、対象9種)」を実装。
  遺業能力はルール上「発動するかどうかを本人が選べる」ため、カードが破壊されるたびに
  即座に自動発動するのではなく、「発動する/発動しない」を選ぶモーダルを表示します
  (複数のカードが同時に破壊された場合は、破壊された順に1件ずつ解決します)。
  対戦相手が検討中の間は、その旨がターン表示に出ます。CPU戦では、CPUの分は
  自動的に判断して即解決します
- マホウは個別実装9種(チャンピオン/ファイナルアタック/ストーム/リバイバル/エイジング/ロイヤリティ/
  デスペラード/ドローイング/ギャザリング)に加え、定型パターンや個別効果に一致するものを実装
  (全80種中80種、つまり全マホウが実際に効果を発揮します)
- イジン・ハイケイの固有能力についても、「戦場に置かれたとき」「アタッカーになったとき」
  「メインフェイズ/エンドフェイズが開始したとき(自分・相手どちらのフェイズ開始で発動するかの
  両方の記法に対応)」「執筆(ハイケイが場に置かれたとき)」
  「決起(マリョク配置によってマリョクが置かれたとき)」「イジンが場に置かれたとき(色・特性・
  レベル・「執筆」所持などで絞り込み可能、味方・相手どちらの配置も検知)」「自分の戦場の特定色
  イジンがアタッカーになったとき」「イジン・ハイケイが破壊されたとき(自分自身の破壊・味方/相手
  いずれかのイジン破壊のどちらの記法にも対応)」「徴募(戦場にいる間だけでなく自分の墓地に
  ある間も発動できるエンドフェイズ能力。墓地からの発動を観測する能力にも対応)」
  「ブロッカーになったとき(対象選択を伴うものにも対応)」「手札から墓地に置かれたとき(効果で
  捨てられた場合。捨てさせた側ではなく、捨てられたカードの持ち主視点で解決)」で発動する
  トリガー効果の実行基盤を追加し、
  条件判定・対象選択(手札操作画面上でカード選択)を伴う効果を含めて自動処理できるようにしました
  (271種のイジン・ハイケイに個別実装済み)。エンドフェイズ開始時トリガーは「カード名を1つ宣言し、
  山札の上やガーディアンをめくって一致すれば強力な効果を発動できる」というカード名宣言型の
  対象選択(専用の入力補助付き)にも対応しています。「アタック+N」「ブロック+N」の継続的なパワー修正、
  ブロック不可・パワー条件付き被ブロック不可などの継続的な戦闘修正にも対応しています。「戦場の
  イジンすべては、このターンに限り色/特性◯◯を得る」という一時的な色・特性付与や、
  「これが戦場にある間、レベルN以下/特性◯◯のイジンは特性・即応を得る」という常在型の
  フィールド付与にも対応し、色・特性を条件とする既存の判定処理すべてに反映されます。
  「カードを裏向きで戦場に置く」「戦場のカードをその場で裏にする」は、裏向き・秘匿という
  性質が完全に一致する既存のガーディアンゾーンを流用して実装しています。
- 公式ルール補足PDF(EXRule)で定義されている特殊システムをすべて実装:
  - **冥府発動**: 色条件・レベル条件・魔力コストを無視して墓地からマホウを発動(対象49種、
    実効果を持つ既存マホウのうち48種で即使用可能)
  - **反魂**: 自分のガーディアン1体を山札の下に戻す代償に、墓地のイジンを召喚権を使わず戦場に置く
    (対象14種)
  - **スタンド**: 色条件を満たしていれば、裏向きのマリョクを表にして戦場に置き、そのままブロッカーに
    できる(対象6種)
  - **装備**: イジン召喚時に魔力ゾーン・ハイケイのカードを装備させ、アタック+N/ブロック+N/パワー+N
    などの単純な修正を実際に付与(装備の着脱自体は対象15種すべてに対応、単純な数値・キーワード修正は
    11種(安宅船「装備者がアタッカーの場合、寝ているイジンも味方アタッカーに選べる」、ホプロン
    「バトルの間、自分の戦場のイジンは能力によって破壊されない」を含む)、
    対象選択不要な誘発型能力(アタッカーになったとき・破壊されたとき等)は4種)
  - **冥装**: マホウ使用によって墓地に置かれた際、またはカード自身が常に持つ性質として、
    墓地にある間だけイジン召喚時の装備品として提供される(対象7種: パイロオーラ/ハイドロオーラ/
    クロロオーラ/ジオオーラ/エアロオーラ/ホムンクルス/マザーグース)
  - **モータル**: バトル解決で(破壊されずに)勝ったなら、アタッカーのまま次のブロックへ続行
- CPU対戦: マナ配置→召喚(装備・反魂含む)→ハイケイ設置→マホウ使用(冥府発動含む)→アタックの順で
  行動し、ブロック時はガーディアン・スタンドを含めて盾に使うヒューリスティックAI。トリガー効果の
  対象選択にも簡易ロジックで対応。使用デッキは環境デッキ29種からランダムに選択
- 手札・場・魔力ゾーン・墓地すべてのカードを公式サイトの実カード画像で表示
- スマートフォン対応: 画面幅に応じてレイアウトが自動調整され、パソコン・スマートフォンどちらでも
  1画面に収まる形で対戦できます
- デッキ編集画面: 全カードから40枚以上・同名4枚まで(「デッキに何枚でも入れてよい」指定カードは
  無制限)のオリジナルデッキを、公式サイトのカード画像付きで組んでブラウザに保存でき、
  人対人・CPU対戦どちらでも使用可能([sweetpotato氏のイジンデンデッキ作成ツール](https://sweetpotato.github.io/ijinden-deck-builder/)のUIを参考に実装)

## カードデータについて

カードデータ(名前・色・レベル・パワー・ルールテキスト・遺業能力・公式カード画像URLなど)は、
ファン制作のデッキ構築ツール[イジンデン デッキ作成](https://sweetpotato.github.io/ijinden-deck-builder/)
(sweetpotato氏, MIT License)が保持しているカードデータベース(576件、公式サイトの表記を
構造化したもの)を利用しています。同名・同色・同ステータスの完全な再録は1枚に統合し、
536件のユニークカードを収録しています。カード画像は元データの`imageUrl`が指す公式サイト
(one-draw.jp)の画像をそのまま参照表示しています。

赤・青・緑・黄・紫の5色それぞれについて、公式カードのみを使って自動生成される40枚の
スターターデッキ(デッキ未編集時の簡易デッキ)を用意しています。無色カードはどの色の
デッキにも採用され、複数色にまたがるカードはデータとして保持しつつ自動デッキ生成の対象外です。

デッキ編集画面では、この536種のカードから自由に40枚以上のオリジナルデッキを組めます
(同名カード4枚まで)。組んだデッキはブラウザのlocalStorageに保存され、人対人・CPU対戦の
どちらでも使用されます。

CPU対戦の相手デッキは、「天草絵巻」サイト(ijinden-amakusaemaki, 非公式ファンサイト)の
「イジデキ」ページに掲載されていた第3弾〜第6弾環境のデッキ紹介29種を実カードへマッピングした
ものからランダムに選ばれます(`server/game/premade_decks.json`)。掲載画像の解像度上、
判読できなかった数枚のカードについては、同じ色のマリョクで代替しています。

## スコープ外・簡略化している点

- イジン約320種・ハイケイ全60種・マホウ全80種・マリョク全72種、すべてのカードで固有テキストを
  実装済みです(基本のキーワード能力・遺業能力の定型パターンに加え、個別の常在効果・トリガー
  効果まで1枚ずつ対応しています)。ただし、以下のようなごく一部の記述は、実装の複雑さ・
  リスクに対して効果が極めて限定的なため、意図的にスコープ外としています。
  - 「見せて」「対象を選んで」のような、本来プレイヤーが任意に選ぶ対象選択の一部は、
    最もレベルが高い/低い候補や相手側を優先するなど、既存の`_auto`系トリガーと同じ方針で
    自動選択します(徴募・木霊以外の対象選択全般に共通する簡略化)。
  - 装備の「装備：」に書かれた誘発型・条件付きの固有能力は基本的に実装済みですが、装備の
    着脱自体は常に正しく動作します。
  - 「この能力自体は能力によって失われない」のような、能力抑制効果自身をさらなる能力抑制
    から守る自己言及的な記述は、二重に抑制し合うカードの組み合わせが実質的に存在しないため
    未対応です。
  - 一部のカードの「戦場を離れない/墓地を離れない」といった、対象を除去全般から保護する
    記述は、除去経路が非常に多いため、代表的な経路のみ対応しています。
  - タップ/アンタップを観測する能力は、簡略化として「アタック宣言によるタップ」のみを
    対象とし、能力によるタップ・アンタップは対象外としています。
  - 足利義満・エンリケ航海王子など、他のカードに新しい誘発型能力を動的に付与する記述は、
    影響が非常に広範囲に及ぶため、静的な数値ボーナス部分のみ実装し、動的な能力付与自体は
    一部スコープ外としています。
- 木霊の対象選択(手札・墓地のどのイジンを戦場に置くか)は、遺業能力発動モーダル上で
  プレイヤー自身が候補一覧(名前・レベル)から選択します。
- 「他のカードの能力をすべて奪う」系(福沢諭吉/近松門左衛門/藤原不比等/蝦夷共和国)は、
  トリガー発火関数・遺業能力解決など約18箇所を横断する汎用の能力抑制判定
  (isAbilitySuppressed)を実装済みです。ただし近松門左衛門の「執筆」による
  「自分の戦場のハイケイすべては、このターンに限りパワー7000のイジンでもある」は、
  ハイケイという型を一時的にイジンとしても扱う変化が、対象選択・召喚権・レベル計算など
  多数の箇所に波及するため、能力抑制効果本体のみ実装し、この一文はスコープ外としています。
  円形闘技場(自分のターンの間、自分の戦場のガーディアンはパワー3000の即応イジンでも
  ある)は、ガーディアンの本来のカード(伏せられたまま)を一切参照しない「パワー3000
  固定・能力なしの匿名の攻撃者」として扱うことで実装済みです(CPU側はこの選択肢を
  積極的には使いません)。黄金時代(相手の手札が3枚以下なら相手の戦場のイジンは
  パワー-2000を得る)は、effectivePower自体にこの条件付きデバフを組み込むことで、
  呼び出し箇所を一切変更せずに実装済みです。遠征軍の第1文(山札から墓地に置かれた
  ときのバトル中断+ターン強制終了)は、任意の効果解決の途中では実際のendTurn呼び出しを
  行わず、各プレイヤー操作の末尾でのみ遅延処理する設計(pendingForcedTurnEnd)により
  実装済みです。
- 宮本武蔵の「カードを2つ以上装備している間」は未実装です。本エンジンの装備システムは
  1体のイジンにつき装備品1枚までを前提に設計されているため、複数装備という仕様自体に
  対応するには装備システム全体の再設計が必要となり、スコープ外としています(戦場に
  「剣術」イジンが置かれたときにパワー2000以下の相手イジンを破壊する、もう一方の
  効果は実装済みです)。
- 「寝たとき」に発動する能力(岡田以蔵/孫権など)は、アタック宣言によるタップのみを
  対象としています(能力によって強制的にタップされる場合は対象外)。同様に、能力に
  よってカードが自分の戦場を離れたときに発動する能力(アダム・ラクスマンなど)は、
  能力による破壊(destroyFieldOrGuardian)のみを対象とし、効果で手札・魔力ゾーン・
  山札に戻す形での離脱は対象外としています。
- マッチ戦・サイドデッキ・手札引き直しなどのオプションルールは未実装です。
- 多色カードを使った複数色混合デッキの自動構築(簡易デッキ)は行っていません(手動デッキ編集では
  色を問わず自由に組み合わせ可能です)。
- 切断時の再接続には対応していません(接続が切れると対戦相手に通知だけ行われます)。
- CPU AIは強さを追求しておらず、破綻しない範囲の簡易ヒューリスティックです。

## 構成

```
server/
  index.js        Express + Socket.io サーバー本体
  rooms.js         部屋管理・ソケットイベントの振り分け・CPU対戦のオーケストレーション
  game/
    cards.js       カードマスタのロードとスターターデッキ生成・カスタムデッキ検証
    cards_data.json 公式カードリスト(第1弾〜第6弾)から抽出・統合したカードデータ
    premade_decks.js/.json  CPU対戦用の環境デッキ29種(ランダム選出)
    engine.js      ルールエンジン(状態遷移・アクション処理)
    bot.js         CPU対戦のヒューリスティックAI
    serialize.js   対戦相手に非公開情報を隠したクライアント向け状態生成
public/
  index.html / css/style.css / js/main.js   フロントエンド(バニラJS, ビルド不要)
  img/           ロビー・対戦結果画面用の公認キャラクターイラスト
```
